# Core Engineering Principles

## Purpose

All development MUST follow these principles.

## Principles

1. Understand before modifying.
2. Human approval precedes every action; nothing runs without explicit confirmation.
2. Reuse before creating.
3. Follow existing architecture before introducing new architecture.
4. Prefer explicit code over unnecessary abstraction.
5. Keep business logic out of presentation layers.
6. Keep infrastructure concerns separated from domain logic.
7. Maintain backward compatibility unless explicitly approved otherwise.
8. Validate changes before declaring work complete.
9. Never silently change database structure, API contracts, authentication mechanisms, or deployment configuration.
10. Documentation must reflect the actual implementation.
11. Do not duplicate functionality that already exists.
12. Do not introduce new dependencies without justification.
13. Security, observability, testing, and maintainability are production requirements, not optional enhancements.
